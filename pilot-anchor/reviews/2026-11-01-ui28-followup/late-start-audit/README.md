# UI28a「3秒」の判定と注意表示の監査

2026-11-01。実機で「4秒くらいまで注意が出ない」と感じたという報告を受けた、現行実装の確認。UI28aのCSS確定後に全43項目を再実行し、結果の全資産SHA-256が最終ソースと一致することを確認した。この監査ではアプリの runtime、閾値、待機式は変更していない。参加者データ・サーバー送信は使っていない。

## 確認できたこと

3秒は、スタートへの pointerdown（選択肢表示と同じ時刻）から、スタート矩形の外側4pxを初めて越えた dispatched pointermove までの区間。回答完了までの時間ではない。`trial-recorder.js:25`、`:47`、`:68`〜`:76`、`app.js:1539`〜`:1571`。

有効回答の終了時に `rt_ms > 3000` を評価する。通常課題には、保持中の3秒到達・4秒到達で注意を表示するタイマーはない。通常課題では回答後に「迷い」「自信」を答え、評定送信後に次の課題を表示する直前で注意画面へ切り替わる。`app.js:1630`〜`:1685`、`:1812`〜`:1820`、`:1432`〜`:1444`。注意は種類ごと5回までで、直後が休憩やマイク確認の場合はそれを挟む。ブロック終了時は次の段階へ進むため、すべての late flag が直後の注意表示と一対一になるわけではない。

表示用の文章は「3秒以上」だが、判定は厳密には「3秒を超える」。この監査では文言・閾値とも変更していない。

| 枠外4pxを越えた記録時刻 − 押下時刻 | lateStart | 本番の評定送信後 | 練習の評定送信後 | 追加問題 |
|---|---|---|---|---|
| 2999ms | false | 次問 | 次問 | 次問 |
| 3000ms | false | 次問 | 次問 | 次問 |
| 3001ms | true | 注意画面 | 練習用の確認画面 | 次問（フラグのみ保存） |
| 4000ms | true | 注意画面 | 練習用の確認画面 | 次問（フラグのみ保存） |

各条件をChrome上の実アプリのpointer handlerで検証した。境界を正確に作るため、この表の入力は合成PointerEventに明示したtimeStampを付けた。ブラウザが自然に入力を配送したときの精度を示す試験ではない。幾何境界も、枠の4px外ちょうどでは未退出、4.5px外で退出を確認した。`rt_ms` は小数点以下2桁へ丸めた後に閾値と比較される。

## 実時間で4秒保持した画面

ChromeのCDP touchで押したままにし、撮影の直前に実測した経過時刻を `results.json` に保存した。

- 本番：約1秒、約3秒、約4秒のいずれも、課題画面のまま。STARTは「スタート」、coach非表示、taskMsg空、late notice非表示。各撮影時点の実測値は `results.json` の `states` を正本とする。
- その後、約4.1秒で枠から出て回答すると `lateStart=true` となり、まず評定画面へ進む。評定を送信して初めて注意画面が出る。記録された正確な `rt_ms` は `results.json` の `real hold is late but first opens rating` を参照。

## 4秒前後の別処理との区別

- `app.js:1530` の4000msは、練習で問題文の表示後すぐスタートに触れ、開始が受け付けられなかったときの案内を消す時間。3秒の初動判定とは別。
- `tutorial-view.js:30` の4000msは、guidedでスタート以外に触れた・枠外で離した場合のhintを消す時間。待ってから表示する時間ではない。
- `app.js:1213` の未開始案内は練習限定で8000ms。開始押下で解除され、recording中は出ない。近くの古いコメントには4秒と残っているが、実行値は8000ms。
- 例題の導入帯2200ms＋500ms後の開始案内は、未開始の例題だけ。記録中・通常課題には出ない。
- 説明ページの「次へ」の強調は文字量・読速に基づく別処理。課題の3秒判定には使わない。
- 枠を出た後に3秒以上止まった場合の `stopFlag` は記録のみで、注意を出さない。
- 注意画面自体は `.screen.active { display:flex }` の切替で表示し、1秒の表示遅延やフェードイン待ちはない。

したがって、現行コードに「3秒＋1秒の猶予」や「4秒で遅い初動警告を出す」処理は確認されなかった。実機で見えた表示が何であったか、OS・ブラウザによる実イベント配送がどうだったかまでは、このローカルChrome検証だけでは断定しない。

## 再現と成果物

43 checksがすべてPASS。`results.json` は検証対象資産のSHA-256、境界条件、保持中の状態、JavaScriptエラーと外部通信が0件であることを含む。境界試験では早出し・説明待機を切って論点を分離し、本番の実時間保持では表示から押下までの条件を満たした状態で確認した。

再現スクリプトは `tools/pilot-anchor/test-ui28-late-start.cjs`。`PLAYWRIGHT_MODULE` と `CHROME_PATH` を設定し `node tools/pilot-anchor/test-ui28-late-start.cjs` で実行する。検証するアプリのディレクトリは `APP_ROOT`、出力先は `OUTPUT_DIR` で指定できる。省略時はスクリプトと同じアプリディレクトリを使い、本記録のfollowupディレクトリへ出力するため、初回UI28レビューを上書きしない。必要な検証用フックはブラウザへ配るメモリ上のコピーだけへ挿入し、配布ファイルには加えていない。既存のUI28レビュー出力は上書きしていない。
