# UI28a：実機報告後の配置補修と3秒判定の監査

2026-11-01。初回UI28の[実装・公開記録](../2026-11-01-ui28/README.md)を保持し、今回の補修を `2026-11-01-ui28a` として記録する。持ち方の位置合わせは実装・ローカル検証済み。公開状態は配信照合後に更新する。

## 実機報告と補修対象

ユーザーは、持ち方だけが上部に寄り、2ページ目以降と「実施後のアンケート」の見出し・ページ番号・本文開始位置がそろっていないと報告した。「その他」の入力時には一時スクロールでき、キーボードを閉じるとスクロールがなくなることを実機で確認しており、キーボードを理由に常時上部へ寄せる必要はないという指示だった。

今回の補修では、持ち方と後続の事後アンケートの見出し・番号・本文領域の開始位置をそろえる。持ち方の8択・2列・任意入力・質問文・回答値は初回UI28と同じ。持ち方の冒頭には元からあるアンケートの案内文を残すため、質問文そのものと本文領域の先頭は区別する。

通常サイズでは従来の2ページ目に近い共通の上余白を使い、小さい有効高さでは共通の余白を減らす。402×759では見出しの開始が93px、375×700では24pxとなる。キーボードを理由とする持ち方専用の上端固定は行わない。説明の文言が変わらないため `instructionVersion` は初回UI28を維持し、開始時の `appVersion` と配布資産のSHAで補修を区別する。

## 表示検証

- [14サイズ・660チェック](layout-results.json)：持ち方の未選択・その他表示・記入済みの42状態でスクロール・文字欠け・重なりなし。全19ページの見出し・番号・本文領域の開始位置を比較し、各ページの末尾操作へ到達できることを確認。
- [修正前との294比較](scroll-comparison.json)：持ち方42状態と後続18ページ×14サイズで、スクロール量の増加なし。
- [切り替え境界10サイズ・472チェック](boundaries/layout-results.json)と[210比較](boundaries/scroll-comparison.json)：幅375/402px、高さ600/601/620/640/641pxを追加確認。持ち方の3状態でスクロール不要、修正前からスクロール量の増加なし。
- 375×700、390×730、402×759以上の既存対象サイズでは全19ページがスクロール不要。375×667/548で元から必要な長文ページのスクロールは維持または減少。
- 配布資産契約10件、bootstrap56件を確認。本文・設問・選択肢と同意・保存系の不変を照合した。

[修正前後と2ページ目の比較](index.html)を参照。これらはChromeのタッチエミュレーションによる検証で、UI28aの実機・キーボード表示中の再確認とは区別する。

振り返り説明の案1、初回待機と既読ページへ戻った際の待機免除は、ユーザーから問題なしと報告された。通常問題の操作も概ね問題なしという報告だった。端末・OS・ブラウザの版は未申告であり、全端末の確認やDriveの保存原本照合が済んだとは扱わない。

## 3秒の再点検

[境界・実時間・表示の監査](late-start-audit/README.md)を参照。スタートを押してから枠外へ初めて出るまでの記録値を3,000msと比較する。3,000msちょうどは対象外、3,001msから遅い初動として記録される。1秒の猶予はない。本番の注意画面は、回答と振り返りの終了後に表示される。3秒経過した瞬間に操作を中断するタイマーではない。

閾値・初動の測り方・注意の表示タイミングは今回変更しない。実機で約4秒と感じた表示が何であったかは、この監査だけでは特定しない。
