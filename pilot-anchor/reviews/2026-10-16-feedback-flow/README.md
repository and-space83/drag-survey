# 練習の確認・本番注意を一続きで比べる仮画面

本番への採用を決める前の比較用です。前の問題の回答・注意条件は合成して用意し、その回答の迷い・自信の振り返りから、操作確認・休憩・次の問題まで連続して触ります。最初の回答を選び直す画面ではなく、実際に指を運んで回答できるのは確認後の次問からです。本番のファイルや既存参加者のデータは変更しません。

親ページの「振り返りからやり直す」は迷い→自信から始めます。「確認・休憩から見比べる」はその前の振り返りを合成済みにして、比較対象の画面から始めます。後者で開いた場合は、各ケースの試し方のうち、すでに飛ばした振り返りの操作は不要です。

## 比べる範囲

- 練習で確認するルールが1つの例と、early・late・releaseの3つが重なる例。
- 練習5問目の確認を終えて、既存の練習完了から本人の操作で本番へ進む例。
- 本番のearly・late・early_late、それぞれの注意。注意なしも対照に含めます。
- 20問後の休憩に、前問の注意が続く例と、そのまま次問へ進む例。
- early・lateとも5回の表示上限へ達しており、観測があっても追加の注意を出さない休憩の対照。

対象は主な10ケースと上限到達の追加1ケース、計11ケースです。ID・説明・触り方、正確な現行の文言、候補の文言、変更理由と保持する条件は [changes-data.js](changes-data.js) に置きます。ここにある文案と画面構成は検討案です。採用済みの仕様や、理解・離脱を改善する効果が実証されたものではありません。

## 候補で変える表示

練習では該当したルールを順に示します。長かった初動の説明は「3秒の対象区間＋実演」と「動かしながら考える＋自分のペース＋理由」の2画面に分け、3ルールなら4画面、遅い初動だけなら2画面にします。初動の確認チェックは後半に1つだけ置き、元の3ルールの確認条件と記録は増やしません。早い開始と離す範囲は本文と図の重複を減らし、進捗を見出しと同じ行にまとめます。本文16px・タイトル22pxを保ち、通常の375×548・375×700・402×759ではスクロールせず全体を見渡せる構成です。文字を拡大した場合などは、内容を隠さずスクロールで読めます。前へ戻ってもチェックを保持し、最後の確認後はアプリ本来の終了判定へ戻します。「練習を続ける」だけを固定せず、5問目の後に架空の6問目を作りません。

本番では次の問題でする行動を先に、前問の観測を補足に置きます。両方の注意は短い2カードを1画面へまとめ、1回の「確認して次の問題へ」で終えます。長い再講習や新しい理解クイズは追加しません。3秒はスタートに触れてから枠を出るまでで、回答を終える期限ではありません。

休憩の順序は現行と同じ「休憩→前問の注意→次問」です。候補は実際に注意が続く場合だけ「続けると、次の問題の前に操作のポイントを確認します。」を足します。注意の観測欄も「休憩前の問題の記録」とし、突然前の問題へ戻った印象を減らす案です。回数上限等で注意が出ない場合は予告しません。

## 保つ境界

- 現行の問題・選択肢・課題パーツの配置・評定の質問と選択肢は保ちます。
- 練習の確認対象と順序、全項目の確認、練習5問と終了判定を保ちます。
- 本番注意の発火条件、種類ごとの5回上限、両方を1回で示す扱いを保ちます。
- 次の問題文を表示する前に注意を終え、説明時間を次問の読解時間に混ぜません。確定済みの評定時間も増やしません。
- 観測した時間を伝え、「読んでいない」「考えていない」と断定しません。チェックや滞在は理解の証明にしません。
- 追加の不注意判定・謝礼条件・解析除外を作りません。実演の経路や一定の速度をまねするよう求めません。

現行文言の入口は本番 `index.html` の `PRACTICE_RULES`、`showPracticeCheck`、`NOTICE_HTML`、`showStopNotice`、`nextTrial`、`presentStimulus`、`showBreak` です。研究仕様は `research/sources/experiment-design.md` §6-6 項24–26・30–35を参照します。このレビューで採用確定の記録は行いません。

## 実装・確認記録

入口は [index.html](index.html)。`app/` の14資産は着手時の公開ui20を凍結した比較元です。ハッシュは [source-manifest.json](source-manifest.json)。作業中に別の変更が本番の作業フォルダへ入っても、再生成はこの凍結コピーだけを使い、比較元を入れ替えません。

`build.cjs` は元の `app/index.html` を変更せず、比較専用の `preview.html` と `preview-runtime.js` を生成します。通常のアプリ処理へ `fixture-bridge.js` だけを注入して、確認用の前問・観測条件・開始位置を用意します。候補では表示関数だけを `candidate-ui.js` で補い、通常の評定・次問・休憩・確認後の進行は元の処理を使います。`verify.cjs` は、注入部分を除くと元の実行コードへ戻ることも確認します。

前の回答は設定済みなので、操作は迷い・自信の振り返りからです。「確認・休憩から見比べる」は、振り返りにも仮の回答を入れて説明の入口へ進めます。その後に表示される次の問題は、実際に指で運んで試せます。

仮の状態を用意している範囲と、元の処理による動作を混同しません。今回のページで注意の判定や理解度を実測しているわけではありません。候補のチェック・ページ送り・補足表示・休憩予告の変更も、採用済みの研究手続きとはしません。

### 保存・通信の隔離

- 両版とも固定した `go=task&debug=1&upload=0&mic=0` の確認モードだけで起動します。
- `fixture-bootstrap.js` がこのページのStorageをメモリー内のものへ置き換えます。既存の参加者保存領域は使用しません。
- 接続・Workerは禁止するCSPを付け、fetch / XHR / sendBeaconも仮画面内で遮断します。
- 保存しない架空回答に離脱確認が出ないよう、仮画面だけbeforeunloadの伝播を止めます。本番の離脱確認は変更しません。
- 永続保存・再開や収集先への送信は、この比較の対象ではありません。読み込み直すとケースの最初へ戻ります。既存の保存確認Siteとは別の画面です。

### 再生成・検証

Node.js・Playwright・Chromeを使います。`PLAYWRIGHT_MODULE` でPlaywrightの場所を指定できます。

```powershell
node tools/pilot-anchor/reviews/2026-10-16-feedback-flow/build.cjs
node tools/pilot-anchor/reviews/2026-10-16-feedback-flow/test-flow.cjs
node tools/pilot-anchor/reviews/2026-10-16-feedback-flow/test-comparison.cjs
node tools/pilot-anchor/reviews/2026-10-16-feedback-flow/verify.cjs
```

結果は [verification.json](verification.json) を入口に、実フローの `qa-results.json`、比較ページの `comparison-results.json` と `qa/` の画面画像を参照します。375×548・375×700等で、長い部分のスクロール、続きを示す案内、確認・戻る・次への到達、現行と候補の分岐と記録の一致を確認します。親ページはPC横並びとスマホ切替の両方を操作します。

検証はChromeのタッチエミュレーションです。iPhone Safari実機・初見の理解改善・実際のデータ回収を確認済みとする結果ではありません。
