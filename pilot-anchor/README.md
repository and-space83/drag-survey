## このアプリの目的

研究全体の主問いは「ドラッグ軌道から各設問への主観的確信度を機械学習で予測できるか」。本アプリはその前段で、**「Web × モバイル × ドラッグ」という取得系が、先行研究で確立した『難易度 → 運動指標』の効果を再現するかを実機で確認**するためのもの。アンカー課題は客観難易度が既知なので、本実験の本筋 (主観確信度予測) に進む前の妥当性確認として使う。

主観評定は **① アンカーでは取得しない**方針（タスクの性質上、確信度は構成的に変動しないため）。評定は **②③ (`?block=value` / `?block=moral` / `?block=combo`) で有効化**され、各試行直後に**2項目 (迷い・自信) ×5段階**を提示する (`CONFIG.ratings`。難しさは第三パイロットで削除)。

## 参加者の動作

1. スマートフォンで URL を開く（アプリインストール不要）
2. 必須: 名前・年齢・機種名(分かる範囲で)・性別(回答しない可)・利き手を入力 (事前アンケート、全項目そろうと開始可)
3. ~~環境音チェック (マイク)~~ は **2026-09-26 に廃止** (既定 OFF。`?mic=1` で旧仕様を有効化できる)。moral を含むセッションでは**読速ベースライン** (短文4本を読了タップ)
4. 操作説明と練習 → 本番。①は正解3連続、②は有効ドラッグ2連続を練習の基準とし、未達なら補充する。③は練習5問で本番へ進み、基準の達成状況を記録する。評定の説明は3ページ。本番の通常項目は①84 / ②24 / ③49 / ②③統合73問で、②③には既定で各ブロック6問の注意チェックを加える。統合 (`combo`) は冒頭に統合練習 (各ブロック2問)
5. 各試行 (上部の「↻ 操作の説明」で本番中も説明を見直せる。見直しは待ち時間なし・画面右上の「× 閉じる」で途中終了): 問題文を読む → 下中央の**スタートに指を置いた瞬間に選択肢が出る** → 選ぶ方のボックス (①は数が大きい方) へ**指を離さず**ドラッグ → 離す (評定ブロックは直後に迷い・自信の2項目評定)。選択肢が出てからスタートの範囲を出るまで3秒を超えた試行は評定送信後に案内画面 (`lateStart`)。**動き出した後の停止は記録のみで、注意画面を出さない**。騒音の案内は旧マイク機能を明示的に有効化した場合のみ
6. moral を含むクラウド配布では、通常の本番後に追加10問 (`phase="instructed"`) を実施してから事後アンケートへ進む。その後、「直前どう持って・どの指で操作したか」を1つ選択 (5択)。評定ブロック (②③) ではさらに、状態・環境・習熟・ふりかえり・課題の感じ方・自己報告の22項目と使いにくさアンケートを末尾に1回提示する。**2〜3問ずつのページ送り**で、持ち方・使いにくさ・任意の自由記述を含む全13ページ。対面用 (`kiosk` / `stop`) は追加10問と拡充した22項目を省き、操作に関する質問を残す
7. クラウド配布では**データは自動送信**される (「✅ データは送信されました。」表示)。完了画面に**完了コード** (XXXX-XXXX) が表示される (募集サイト経由の場合は納品欄に入力してもらう。`?ccode=0` で非表示)。対面では担当者の送信操作を待つ
   - 自動送信に失敗した場合や送信を無効化している場合は「データを保存 (JSON)」「データを送る (共有)」から、手動で研究者に送れる (LINE / メール / Drive)
   - 本番・評定・追加問題・事後アンケートの途中で画面が消えた (再読込・タブ破棄) ときは、**同じブラウザで3時間以内に同じURLを開き直すと「続きから再開」**できる (データは完走時にまとめて送信)。それ以外の中断データは保存ボタンから手動保存できる
   - 完了コード横のコピーアイコンを押すとコピー結果を表示する。連絡先メールアドレスを設定している場合は下の「メールで送信する」からメールアプリを開ける

> 事前=特性 (年齢・性別・利き手)、事後=状態 (持ち方+操作した指=grip) と分けるのは、操作手を事前に意識させて自然な使い方が崩れるのを避けるため。

## 記録されるデータ (1試行あたり)

- **Pointer Events 列**: `pointerdown` / `pointermove` / `pointerup`、raw `event.timeStamp`、surface 相対座標、Android Chrome の `getCoalescedEvents` 含む
- **試行メタ**: 数値ペア・congruency・大きい数の左右位置・選択結果・正誤・RT/MT/total の proxy
- **参加者属性**: 氏名（参加確認・謝礼照合用。解析時は研究用IDに置換）・年齢・機種名・性別・利き手 (事前) / grip=持ち方+操作した指 (事後、5択)
- **端末情報**: UA・画面サイズ・DPR・推定リフレッシュレート
- **セッション情報**: `device.sessionId` (開始時に発行し、再開・再送でも固定するUUID)、`appVersion`、`collectionPlan` (そのセッションの事後項目・追加問題・注意チェックの有効状態)
- **geometry スナップショット**: 試行ごとの START / 選択肢 / surface 位置 (空間正規化用)
- **実効サンプリングレート**: `dt>0` ガード付き
- **実施環境・品質 (2026-07-21/22 追加)**: 画面離脱 `vis:{count,totalMs}`・`device.{wakeLock, completionCode, readingBaseline}`。環境音 `noise` / `device.mic` は 2026-09-26 に廃止 (既定 null / mode=off)
- **開始手続き (2026-09-26)**: `preStartMs` (問題文の表示〜押下)・`revealT` (=押下・選択肢の出現)・`initiationT` (動き出し)・`rt_ms` (出現〜動き出し)・`lateStart`・`earlyStart`・`stopsAfterInit`・`stopFlag`・`stopNotice`。`device.startMode='press'`

完全な data spec は [`index.html`](index.html) 冒頭のコメントを参照。

| `?pid=`/`?age=`/`?model=`/`?sex=`/`?hand=` | — | 事前アンケートのプリセット。`?intro=0` で埋まった欄を隠す |
| `?rtut=0` | ON | 振り返りの説明 = 評定チュートリアル (3ページ: 導入・迷い・自信、2026-09-12) を省く |
| `?hud=1` | OFF | 課題画面に経過時間・直前1問の所要秒 (自分でリハーサルするとき用。参加者に時計を見せると時間圧がかかるので本番では付けない) |
| `?cohort=` | — | 標本タグ (`device.cohort`)。解析で母集団を分けるための目印。受け口はこの値のサブフォルダに保存する |
| `?study=` | — | 実験名 (`device.study`)。受け口 (Drive) の保存先サブフォルダ = `study` (無ければ `cohort`)。実験ごとにデータを混ぜないため |
| `?ccode=0` | 表示 | 完了コードの非表示 (身内配布用。データへの記録は常に行う) |

データ回収は完了時に GAS Web アプリへ自動 POST → Google Drive `pilot-anchor-data/` に保存。失敗時はダウンロード / Web Share にフォールバック。受け口の実装・デプロイ手順は private リポの `tools/pilot-anchor/gas-collector.gs` / `DEPLOY.md`。

新しい受け口は `device.sessionId` と最終データを照合し、同じデータの再送ではファイルを増やさず受領済みとして応答する。構造・サイズの検査と再試行できるエラーの区別も行う。これらは **GAS側の既存デプロイを更新して有効になる仕様**で、公開サイトの4ファイルを置き換えるだけでは受け口は更新されない。

## 課題仕様

- **刺激**: アラビア数字、物理サイズ比 2:1 (大: `--choice-w` の 22vmin、小: 11vmin)
- **数値ペア**: `1v2` / `2v8` / `8v9` (距離が小さい `8v9` がサイズ効果で最難)
- **congruency**: congruent (大きい数が物理的にも大) / incongruent (大きい数が物理的に小)
- **左右カウンターバランス**: 大きい数の左右配置を均等にして右手バイアスを統制
- **試行構成**: 2 × 3 × 2 = 12 セル × 7 反復 = **84 本番試行**

レイアウト (片手操作向け) は CSS 変数 `--choice-top` (既定 27%) と `--start-bottom` (既定 12%) で調整可。

## ② 価値・選好 (Stage 2) の課題仕様 (`?block=value`)

- **刺激**: 文字2択 (短語句)。上部中央に設問ステム (例「どちらが欲しいですか？」) を固定表示。reach-decision の操作は①と同一。
- **中核操作**: 価値差を3水準で段階化 — **明確** (価値差大→即断・高確信)・**中** (一長一短のトレードオフ)・**拮抗** (価値差最小→迷い)。拮抗は approach 型 (両方魅力) と avoidance 型 (両方イヤ「まだマシな方」) を含む。
- **4ドメイン混在** (消費財 / くじ / 食品 / 価値判断) で方略化を防止。左右CB (高価値側を左右均等)。
- **試行構成**: 24 項目 (価値差3 × ドメイン4 × 各2) を各1回 = **本番 24 試行** + 練習 (ゲート制)。左右CB は項目間で均等 (高価値側を12左12右、水準内4L/4R)。同一設問の2回提示はしない。くじは金額くじ (EV 記録) と賞品くじ (EV なし) の混合。
- **評定 (ON)**: 各試行の選択直後に 2 項目 × 5 段階 (自信 / 迷い。2026-07-15 に難しさを削除)。
- **正誤フィードバックなし** (主観選択のため)。試行メタに domain / 価値差水準 / conflict 型 / くじ EV 差を記録。設計正本は private リポ `research/sources/experiment-design.md §6`。

## ③ 道徳ジレンマ (Stage 2) の課題仕様 (`?block=moral`)

- **刺激**: 場面文ステム + 文字2択 (どうするかの行動選択)。reach-decision の操作は①②と同一。
- **試行構成**: 7類型 (sacrifice / honesty / loyalty / care / promise / autonomy / privacy) × [明確1・中間2・拮抗4] = **本番49問**。既定で注意チェック6問を加え本番55問、続いて追加10問。練習は5問。
- 明確のみ規範整合 `betterSide` を定義 (中・拮抗は null)。左右CB。評定2項目 ON。読速ベースライン (短文4本) が開始前に付く。
- 設計正本は private リポ `research/sources/experiment-design.md §6-5`。

## ②③ 統合セッション (`?block=combo`) と ⑤ 注意チェック

- ②と③を1セッションで通す (第二パイロット以降の配布形態)。ブロック順は既定ランダム (被験者間CB、`?order=vm|mv` で固定可)。練習はセッション冒頭に統合 (本番ブロック順で各2問・1問目に評定チュートリアル)、事後アンケートは末尾で1回。
- **⑤ 注意チェック (既定ON、`?attn=0` で無効)**: 各評定ブロックに指示付き項目 (弱 DQS) を4問埋め込み、各ブロックの最後の2問に infrequency と強 IMC を提示する (振り返りあり)。moral の弱 DQS は10/23/31/42問目。統合では通常項目73問と注意チェック12問で本番計85問、その後に追加10問。完了画面でデブリーフィング (種明かし) を表示。
- データは `device.block="combo"`・`device.seq` にブロック順、各試行に `block` / `isCheck` タグ。解析側は per-trial `block` で value / moral を分離し `isCheck` 試行を主解析から除外する。

## クロスプラットフォーム実装上の注意

- iOS は静止中 `pointermove` を出さない / Android は出す → 生記録のまま保持し後処理で扱う
- 同一 `timeStamp` の重複イベントが発生しうる → `dt>0` ガード必須
- iOS は `timeStamp` 1ms 量子化、Android は小数
- 画面サイズ / DPR が機種で大きく異なる → surface 相対座標 + 毎試行 geometry 記録
- URL バー伸縮で viewport がずれる → 全画面 fixed + surface 相対で対応
- 画面端ドラッグが OS ジェスチャと衝突 → 選択肢を端から ~6% 内側にレイアウト + `touch-action: none`
- マルチタッチ二本目は無視、early release / 短すぎ試行は再呈示

## 技術

- 静的ファイル4つ (`index.html` = マークアップ+エンジン / `app.css` = スタイル / `bank.js` = 刺激バンク / `session-store.js` = 保存・排他・移行) + 静的サーバスクリプトのみ。ビルドステップなし、依存ライブラリなし。
- Pointer Events API ベース。
- データ保存: localStorageへの途中保存・未送信保存、Web Locksによるタブ間排他、ブラウザ標準のダウンロード (Blob URL)。排他API非対応や保存失敗時は案内を表示し、既存データを消さない。
- 送信先は `CONFIG.uploadUrl`。開発用の送信先上書きは localhost の `debug=1` で同一オリジンのURLに限る。`upload=0` と確認モードでは自動送信しない。

## 由来

- 課題: 数値サイズ一致性 (Numeric-Size Congruity)。スマホ・タブレットでの reach-decision 版は Ouellette Zuk (2025) が確立。
- 修論研究の Stage 1 として作成。研究全体のドキュメント・解析計画・先行研究調査は別リポ (private) で管理。
- 取得系 (Pointer Events / `event.timeStamp` 生記録 / `getCoalescedEvents`) は同階層の [../sampling-rate-test/](../sampling-rate-test/) から流用 (60Hz floor の設計根拠もそこで確立)。
